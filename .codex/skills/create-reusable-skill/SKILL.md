# 创建可复用 Skill

## 工作流程

1. 明确 skill 的通用能力，以及应触发该 skill 的用户请求。
2. 使用简短、动词开头、小写连字符格式的名称，不在名称中加入仓库或产品标识。
3. 在 `SKILL.md` 中只保留可复用流程；仓库专用事实、路径、命令、模块和约定放入仓库规则或项目 references。
4. 检查目录名、frontmatter、标题、描述、UI 元数据、默认提示、脚本、references 和 assets，移除无意引入的项目耦合。
5. 必要输入应通过参数或按需查询获得，不得写死仓库结构或本机环境。
6. 使用可用的 skill 校验器检查结果，并确认没有占位内容或过期元数据。

## 可复用性检查

- skill 复制到其他仓库后仍应具备完整意义。
- 目录名必须与 frontmatter 中的 `name` 一致。
- frontmatter 只能包含 `name` 和 `description`；description 必须同时说明能力和触发场景。
- `agents/openai.yaml` 必须使用相同的 skill 名称，默认提示必须显式调用 `$<skill-name>`。
- 通用核心中不得写入仓库名、项目绝对路径、本机用户名、解决方案名、项目模块名或项目专用命令。
- 只有用户明确要求项目特化，且移除项目耦合会破坏 skill 用途时，才创建项目专用 skill。

## 完成汇报

说明 skill 路径、可复用范围、被移出的项目专用内容、验证结果，以及仍然保留的有意耦合。
