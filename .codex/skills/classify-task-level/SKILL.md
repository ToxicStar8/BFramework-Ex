# Classify Task Level

## 完成分级

1. 根据可观察的修改范围、行为影响、依赖跨度和验证难度判断等级。
2. 同时命中多个等级时使用最高等级；无法确定时上调一级。
3. 返回 `任务等级：Lx — <判定依据>`。
4. 范围扩大、出现跨模块影响或验证风险增加时重新分级。

## L1–L4 判定

| 等级 | 判断标准 | 典型任务 | 查询深度 | 计划与验证深度 |
| --- | --- | --- | --- | --- |
| **L1 简单** | 单文件明确位置、行为不变、影响明确的机械性修改 | 普通 typo、注释、日志文本、非敏感的单行变量改名 | 不查询其他主题规范 | 不建立计划；执行最窄静态检查 |
| **L2 局部** | 使用已知模式完成单模块局部行为修改，影响边界明确 | 调用已知 API、修改一个方法或局部分支、局部 bug 修复、跨文件机械替换 | 查询一个直接相关主题 | 仅在多步骤时建立短计划；执行聚焦验证 |
| **L3 功能** | 新功能、跨文件修改或新增完整行为链路 | 新增 UI、网络处理、资源或事件逻辑，修改多个直接协作文件 | 查询完成行为链路所需的全部相关主题 | 建立带验证点的短计划；验证完整行为链路和直接协作边界 |
| **L4 架构** | 模块设计、系统重构、多模块协作或高风险技术边界决策 | 改公共生命周期、通信框架、资源架构、运行时或绑定策略 | 查询所有受影响主题、依赖关系和代表性实现 | 先做影响分析和分阶段计划；覆盖兼容、迁移、回滚及所有适用验证 |

## 升级条件

- L1 涉及 API 名称、序列化字段、UI 节点前缀、事件或协议定义、资源路径、反射或绑定名称时，至少升级为 L2。
- L1 修改跨多个文件、包含多个批量命中位置或需要批处理时，至少升级为 L2，即使已确认行为不变。
- L2 同时影响多个生命周期阶段、跨语言边界、跨消息发送与处理或改变资源所有权时，升级为 L3。
- L3 改变公共契约、模块边界、基础生命周期、协议兼容、热更新边界或构建链路时，升级为 L4。
- 文件数量不是唯一标准：单文件架构决策可以是 L4；跨多个文件且确认行为不变的纯机械替换判为 L2。
- Bug 严重程度不等于任务等级；按定位范围、行为影响和验证难度分级。
- 只读分析按分析范围分级，不能因为不修改文件自动判为 L1。

## 查询范围

- **L1**：只使用目标位置和必要邻近上下文。
- **L2**：使用目标实现、直接引用和一个相关主题。
- **L3**：使用行为链路内全部相关主题与直接协作实现；不扩展到无关主题。
- **L4**：使用所有受影响主题、依赖关系和代表性实现；不把架构级任务等同于读取完整仓库。

信息足以完成判断和执行时停止扩大查询范围。

## 分级示例

- “修正文档里的一个错别字” → **L1**。
- “按现有写法修改一个界面按钮的显隐” → **L2**。
- “批量替换多个文档中的旧产品名，且不涉及敏感标识符” → **L2**。
- “新增一个界面，并接入网络消息和资源加载” → **L3**。
- “重新设计客户端网络层，或迁移脚本运行时” → **L4**。
- “调查偶发空引用，但根因未知且可能跨语言边界” → 初始至少 **L3**，发现公共生命周期缺陷后升级为 **L4**。

## 完成检查

- 确认最终等级符合实际范围。
- 确认查询范围没有低于该等级所需上下文，也没有扩展到无关主题。
- 确认计划和验证深度与等级及实际风险匹配。
